# Deploying a Spring Boot Project Using AWS S3 Bucket and EC2

This guide outlines the steps to deploy a Spring Boot project using AWS S3 as a storage solution and an EC2 instance for hosting the application.

---

## Prerequisites
1. **AWS Account**: Ensure you have an active AWS account.
2. **EC2 Instance**: Launch an EC2 instance to run the Spring Boot application.
3. **Spring Boot Project**: A pre-built Spring Boot REST API project packaged as a `.jar` file.
4. **AWS CLI**: Install and configure the AWS CLI on your local machine and EC2 instance.

---

## Steps

### 1. **Create and Configure an EC2 Instance**
- Launch an EC2 instance from the AWS Management Console.
- Allow inbound traffic for:
    - **Port 22**: For SSH access.
    - **Port 8080**: For accessing the Spring Boot application.
- SSH into the EC2 instance:
  ```bash
  ssh -i "your-key.pem" ec2-user@<public-ip-address>
  ```

### 2. **Build the Spring Boot JAR File**
- Package your Spring Boot project into a JAR file using Maven or Gradle:
  ```bash
  mvn clean package
  ```
- This generates a `.jar` file in the `target` directory (e.g., `my-app.jar`).

---

### 3. **Upload the JAR File to S3**
1. **Log in to AWS Management Console**:
    - Go to **S3** and create a bucket (e.g., `my-spring-boot-bucket`).
2. **Upload JAR File**:
    - Click **Upload** and add your `.jar` file.
    - Note the S3 URL for the file (e.g., `s3://my-spring-boot-bucket/my-app.jar`).

Alternatively, upload using the AWS CLI:
```bash
aws s3 cp target/my-app.jar s3://my-spring-boot-bucket/
```

---

### 4. **Install Java on the EC2 Instance**
- SSH into your EC2 instance and install Java:
  ```bash
  sudo yum update -y        # For Amazon Linux
  sudo yum install java-17 -y
  ```
- Verify Java installation:
  ```bash
  java -version
  ```

---

### 5. **Download the JAR File to the EC2 Instance**
- Use the AWS CLI to download the JAR file:
  ```bash
  aws s3 cp s3://my-spring-boot-bucket/my-app.jar /home/ec2-user/
  ```

---

### 6. **Run the Spring Boot Application**
- Navigate to the directory where the JAR is located:
  ```bash
  cd /home/ec2-user/
  ```
- Start the application:
  ```bash
  java -jar my-app.jar
  ```
- Keep the application running using `nohup`:
  ```bash
  nohup java -jar my-app.jar > app.log 2>&1 &
  ```

---

### 7. **Test the Spring Boot Application**
- Access the application using the EC2 instance's public IP:
  ```text
  http://<ec2-public-ip>:8080
  ```
- Ensure the security group allows traffic on port 8080.

---

### Optional: Automating Deployment with Systemd
To automate application startup:
1. **Create a systemd service file**:
   ```bash
   sudo nano /etc/systemd/system/spring-boot-app.service
   ```
2. **Add the following configuration**:
   ```ini
   [Unit]
   Description=Spring Boot Application
   After=network.target

   [Service]
   User=ec2-user
   WorkingDirectory=/home/ec2-user
   ExecStart=/usr/bin/java -jar /home/ec2-user/my-app.jar
   Restart=on-failure

   [Install]
   WantedBy=multi-user.target
   ```
3. **Enable and start the service**:
   ```bash
   sudo systemctl daemon-reload
   sudo systemctl enable spring-boot-app
   sudo systemctl start spring-boot-app
   ```

Here are some commonly asked **AWS S3 (Simple Storage Service)** interview questions, ranging from basic to advanced levels:

---

### **Basic Questions**
1. **What is Amazon S3?**
    - Answer: Amazon S3 is an object storage service that provides scalability, data availability, security, and performance. It is used for storing and retrieving any amount of data from anywhere on the web.

2. **What are the main features of S3?**
    - Answer:
        - Durability: 99.999999999% (11 nines) durability.
        - Scalability: Unlimited storage.
        - Availability: High availability (99.99% uptime).
        - Versioning: Supports keeping multiple versions of an object.
        - Security: Data encryption at rest and in transit.

3. **What is an S3 bucket?**
    - Answer: An S3 bucket is a container that stores objects (data) in Amazon S3. Each bucket has a globally unique name.

4. **How is data organized in S3?**
    - Answer: Data is stored in buckets as objects. Each object has a unique key within the bucket.

5. **What are the storage classes in S3?**
    - Answer:
        - S3 Standard: High durability, availability, and performance.
        - S3 Intelligent-Tiering: Cost-optimized storage with automatic tiering.
        - S3 Standard-IA (Infrequent Access): For data accessed less frequently.
        - S3 One Zone-IA: Lower cost for infrequently accessed data in a single AZ.
        - S3 Glacier Instant Retrieval: Fast access to archive data.
        - S3 Glacier Flexible Retrieval: Low-cost archival with retrieval times of minutes to hours.
        - S3 Glacier Deep Archive: Lowest-cost storage for long-term data.

---

### **Intermediate Questions**
6. **What is the maximum size of an object in S3?**
    - Answer: The maximum size of a single object is **5 TB**. However, for uploads larger than 5 GB, the **multipart upload** feature must be used.

7. **What is object versioning in S3?**
    - Answer: Object versioning allows you to keep multiple versions of an object in the same bucket, preventing accidental overwrites or deletions.

8. **How do you secure data in S3?**
    - Answer:
        - Use **IAM policies** and **bucket policies** for access control.
        - Enable **encryption at rest** (SSE-S3, SSE-KMS, SSE-C).
        - Enable **encryption in transit** using HTTPS.
        - Use access control lists (ACLs) and block public access as needed.

9. **What is S3 Transfer Acceleration?**
    - Answer: S3 Transfer Acceleration enables fast, easy, and secure transfer of files over long distances by using Amazon's globally distributed edge locations.

10. **What are S3 lifecycle policies?**
    - Answer: Lifecycle policies allow you to define rules to transition objects to different storage classes or delete them automatically after a specified time.

---

### **Advanced Questions**
11. **How does S3 ensure data durability?**
    - Answer: S3 replicates data across multiple availability zones (AZs) to ensure **11 nines** durability.

12. **What is a pre-signed URL, and how is it used?**
    - Answer: A pre-signed URL grants temporary access to a private object in S3. It is used to share objects securely without making them public.

13. **What is the difference between bucket policies and IAM policies?**
    - Answer:
        - **Bucket policies**: Attach directly to an S3 bucket and define actions users/groups can perform on that bucket.
        - **IAM policies**: Attach to IAM users/groups/roles and define their permissions across AWS services.

14. **What is Cross-Region Replication (CRR) in S3?**
    - Answer: CRR automatically replicates objects from one bucket to another bucket in a different AWS region, providing disaster recovery and low-latency access.

15. **What is Event Notification in S3?**
    - Answer: S3 can notify other AWS services (like Lambda, SNS, or SQS) when specific events (e.g., object creation or deletion) occur in a bucket.

16. **How does S3 handle consistency?**
    - Answer:
        - **Read-after-write consistency**: For PUTs of new objects.
        - **Eventual consistency**: For overwrites and deletes.

---

### **Scenario-Based Questions**
17. **How would you optimize S3 costs for infrequently accessed data?**
    - Answer: Use storage classes like S3 Standard-IA, One Zone-IA, or Glacier classes. Implement lifecycle policies to transition objects to lower-cost storage.

18. **How can you make a bucket publicly accessible?**
    - Answer:
        - Disable the "Block Public Access" feature for the bucket.
        - Add a bucket policy allowing public read access.
        - Example policy for public access:
          ```json
          {
            "Version": "2012-10-17",
            "Statement": [
              {
                "Effect": "Allow",
                "Principal": "*",
                "Action": "s3:GetObject",
                "Resource": "arn:aws:s3:::your-bucket-name/*"
              }
            ]
          }
          ```

19. **How would you upload a large file (e.g., 10 GB) to S3?**
    - Answer: Use **multipart upload** to split the file into smaller parts, upload them in parallel, and then combine them.

20. **How do you debug access denied errors for S3?**
    - Answer:
        - Check the bucket policy and IAM policy.
        - Verify permissions for the principal (user, group, or role).
        - Ensure that the bucket isn't blocking public access (if required).
        - Use the AWS **Policy Simulator** to test permissions.

---

### **Key Tips**
- Always mention **real-world examples** of how you used S3 in projects.
- Be familiar with **best practices**, such as enabling versioning, encryption, and logging.
- Prepare for scenario-based questions, focusing on cost optimization, security, and data management.
